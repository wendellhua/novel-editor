# ADR-010：本地访问安全——127.0.0.1 + 一次性 nonce 换 Cookie + Host/Origin 校验
- **状态**：已采纳
- **日期**：2026-10-09

## 背景 (Context)
本地 HTTP 服务能读写全部作品，也持有 API Key。如果不做防护，会面临以下风险：
- 局域网内的其他设备访问这个服务；
- 用户打开的任意恶意网页向 `127.0.0.1` 发跨站请求（CSRF）；
- DNS 重绑定攻击。

## 候选选项 (Options)
1. **不做防护，只监听 127.0.0.1**
   - 缺点：挡不住恶意网页发起的 CSRF 和 DNS 重绑定。
2. **在 URL 中带 token，前端每次请求都附上**
   - 缺点：token 会出现在浏览器历史记录和书签里，泄露面大。
3. **一次性 nonce 换取 HttpOnly 的 SameSite=Strict Cookie，并校验 Host 和 Origin**
   - 优点：拦住跨站请求和 DNS 重绑定；token 不留在 URL 里。
   - 缺点：浏览器 Cookie 被清除后，需要从启动器重新进入。

## 决定 (Decision)
采用选项 3，细节见 ARCHITECTURE §7.1 和 INV-12、INV-17。

**登录方式**
- 启动器打开的地址是 `/auth?n={nonce}`。nonce 只能使用一次，60 秒内有效。
- 校验通过后，服务端写入 Cookie：`ne_session = HMAC(authSecret)`。
- 用户再次双击启动器时，第二个实例会通过 `X-Auth-Secret` 向已经运行的实例申请一个新 nonce，然后打开浏览器。

**请求校验**
- 所有 API 请求都校验 `Host` 头，以防御 DNS 重绑定。
- 写请求额外校验 `Origin` 头，以防御 CSRF。

**页面与密钥**
- CSP 设置为 `connect-src 'self'`，页面只能连接本服务。
- 所有外部请求（大模型、SkillHub）都由服务端代为发出。
- API Key 从不下发给前端。

**会话失效时**
- 前端提示「请从程序重新打开」。
- 处于未授权状态时，前端仍可读取本地 IndexedDB 草稿，不会丢稿。

## 理由 (Rationale)
- 以最少的代码成本，堵住本地 Web 服务最常见的三类攻击，同时不影响「双击就能用」的体验。

## 后果 (Consequences)
- **正面**：恶意网页无法读取或篡改作品，也拿不到 API Key。
- **负面 / 代价**
  - 用户手动在浏览器地址栏输入地址、或使用旧书签时，会因为没有 Cookie 而被拒绝访问，需要从程序重新进入。界面上会给出说明。
  - `authSecret` 存放在本机 `config.json` 中，能读取用户目录的本地程序就能拿到它。这不在本应用的防护范围内。
