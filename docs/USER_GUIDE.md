# NovelEditor 使用说明

NovelEditor 是一个在本机运行的长篇小说写作工具：在浏览器里写作，数据只保存在你自己的电脑上；
可以接入任意 OpenAI 兼容的大模型服务，做错别字检查、编辑审稿、设定与角色一致性检查。

---

## 1. 安装与启动

### Windows 10 / 11（64 位）

1. 把 `NovelEditor.exe` 放到任意文件夹（可以是中文路径），双击运行。不需要安装 Node.js 或其他运行环境。
2. **第一次运行出现蓝色窗口「Windows 已保护你的电脑」（SmartScreen）时**：点「更多信息」→「仍要运行」。
   这是因为程序没有购买代码签名证书，放行一次后不会再提示。杀毒软件拦截时，把 `NovelEditor.exe` 加入信任列表。
3. 程序启动后会自动用默认浏览器打开写作页面，同时有一个黑色控制台窗口——**不要关闭它**，关闭窗口等于退出程序。
4. 关掉浏览器标签后，再次双击 `NovelEditor.exe` 会重新打开页面，不会重复启动。

### macOS（Apple 芯片，macOS 13.5 及以上）

1. 解压 `NovelEditor-mac-arm64.tar.gz`，把 `NovelEditor.app` 拖到「应用程序」文件夹。
2. **第一次打开提示「无法打开」「无法验证开发者」或「已损坏」时**：打开「终端」，执行（路径换成实际位置）：

   ```
   xattr -dr com.apple.quarantine /Applications/NovelEditor.app
   ```

   然后再双击打开。这是因为程序没有经过 Apple 公证，执行一次即可。
3. 程序在后台运行，没有 Dock 图标；关掉浏览器标签后再次双击 `.app` 就会重新打开页面。

### 退出程序

页面右上角「设置」→「关于」→「退出程序」。正在编辑的内容会先保存，正在运行的 AI 检查会暂停，下次可以继续。

---

## 2. 写作

- **作品库**：新建、编辑、删除作品。删除的作品进入作品库右上角的「回收站」，可以恢复。
- **工作区**：左侧是分卷与章节目录，可以拖拽排序、跨卷移动、右键重命名或删除；删除的分卷和章节进入「回收站」（编辑器顶栏右侧）。
- **自动保存**：停止输入片刻后自动保存，编辑器上方显示「已保存」。断网或程序意外退出时，内容会先保存在浏览器草稿里，下次打开时自动恢复。
- **历史版本**：编辑器上方「历史版本」。写作过程中每 10 分钟自动存一个版本（每章保留最近 30 个），也可以手动存版本；AI 修正和恢复版本之前也会自动存一份。
- **输入法问题**：如果某个输入法在编辑器里表现异常，打开编辑器上方的「纯文本」开关，改用系统原生输入框。
- **导出**：编辑器顶栏右侧「导出」，整部作品导出为 TXT 或 Markdown。

## 3. 配置大模型

1. 「设置」→「模型」→「添加模型」，从预设中选择厂商（DeepSeek、通义千问、Kimi、智谱等），填入 API Key 与模型名。
   也可以手动填写任何 OpenAI 兼容服务的地址。
2. 点「测试连接」：程序会探测该模型支持的 JSON 输出方式并自动选择最合适的一档。测试时显示已等待的秒数，可以随时「取消测试」；最长约 2 分钟，没有结果会提示超时。
3. 第一个添加的模型自动成为所有检查任务的默认模型；也可以为每类任务单独指定。

**模型状态**：每个模型旁边的标签表示它最近的情况——「可用」（最近一次测试或 AI 请求成功）、「异常」（最近一次请求因网络、Key、余额、地址、超时等原因失败，下方会写明原因和处理建议）、「未检测」（本次启动后还没有用过，或刚改过地址、Key、模型名）、「测试中」。AI 任务正在使用这个模型时，还会显示有几个请求在进行、排队或重试。
页面右上角的「本地服务已连接」只表示页面和本机的 NovelEditor 程序连着，**不代表模型可用**。

**修改模型配置**：改了 Key、服务地址或模型名后，正在进行的 AI 任务会自动停止旧的请求、按新配置重新发送，不需要重新创建任务。模型异常时（例如请求一直超时），改超时等其他参数也会这样处理。

API Key 只保存在本机数据目录的 `llm.json` 里，界面上只显示掩码，日志中会自动脱敏。

## 4. AI 检查

编辑器顶栏右侧「AI 检查」：

| 类型 | 做什么 | 结果 |
|---|---|---|
| 错别字与标点 | 找出错别字、的地得、标点误用、明显语病 | 可一键修正的问题 |
| 编辑审稿 | 以责任编辑视角看节奏、冲突、人物、对话等 | 逐条意见 + 每章评语 + 整体审稿报告 |
| 设定一致性 | 对照设定库与前文，查世界规则、地理、时间线、物品等矛盾 | 带依据的问题 |
| 角色一致性 | 查外貌、性格、称谓、能力状态、关系、信息越界 | 带依据的问题 |
| AI 味检测 | 找出模板化的套话、空泛的形容与总结、情绪直接说明等「AI 味」表达 | 每处都带改写的问题，可一键优化 |
| 灵感胶囊 | 根据作品设定与基调、剧情记忆、当前剧情和情绪曲线构思接下来的剧情 | 五条剧情发展路线的报告（不改动正文） |
| 智能扩写 | 只根据前文续写当前章节，帮你完成这一章 | 续写结果，确认后插入章末 |
| 设定抽取 | 从正文中抽取人物、地点、势力等设定 | 设定库中的待审核候选 |

- **范围**：整部作品、当前分卷或当前章节；灵感胶囊与智能扩写只能针对当前章节。开始前会显示预计的片段数和输入 token 用量。
- **只查改动过的章节**：勾选后，跳过上次同类检查之后没有改过的章节。
- **任务**：可以暂停、继续、取消；网络中断或额度不足导致失败时，修好后点「重试」，已完成的部分不会重复执行。检查期间可以照常写作。
- **一致性检查需要设定库**：先做一次「设定抽取」并审核入库，设定与角色一致性检查才有比对的基准。

### 处理问题

- 检查完成后右侧打开「问题」面板，问题在正文中以波浪线标出（红色为错误、橙色为可疑、蓝色为建议）。
- 点击列表中的问题会跳到正文对应位置；点击正文中的波浪线会选中列表中的条目。
- 「采纳」按建议修改正文，「采纳全部」一次改完当前范围内所有可修正的问题；修改后可以在编辑器中按 Ctrl+Z（Mac 为 ⌘Z）撤销。
- 只有意见、没有修改建议的问题（如审稿意见）显示「修复」：由 AI 按意见改写这一处文字并直接修正。「全部修复」一次处理当前范围内全部待处理的问题——有建议的按建议改，没有建议的由 AI 改写；修复时显示进度，可以随时「停止」（停止后正文不改动，已生成的建议保留在问题上，可以逐条「采纳」）。修复同样会先存「修正前」历史版本，也可以撤销。修复使用发现该问题时所用的模型，会消耗 token。
- 「忽略」后的问题不会因为再查一次而重新出现。
- 检查之后又改过稿，问题会自动按新正文重新定位；原文已被改掉的标为「已失效」。

### 审稿报告

编辑审稿完成后，点提示中的「查看报告」或检查面板任务列表中的「查看报告」：「整体报告」是全书（或所选范围）的总评与修改建议，
「逐章意见」列出每章的评语和意见，点击意见会跳到正文中对应位置。

### AI 味检测与一键优化

检测完成后提示「发现 N 处 · 一键优化」：确认后按 AI 的改写替换这次找到的全部 AI 味表达（同样先存「修正前」历史版本、可以撤销）。
也可以在问题面板中逐条查看，「采纳」或「忽略」。改写会保留情节信息和设定库中的专有名词。

### 灵感胶囊

打开要接着写的章节，在「AI 检查」中选「灵感胶囊」→「生成灵感」。完成后点「查看」：报告先概括当前局势和最近几章的情绪曲线，
再给出五条方向不同的路线，每条有核心设想、接下来 1～3 章的剧情节拍、张力来源、章末钩子和需要注意的风险。
灵感胶囊只给构思，不会改动正文；本章还没写也可以用，会参考上一章的结尾。

### 智能扩写

打开要完成的章节，在「AI 检查」中选「智能扩写」，选择篇幅（约 1000 / 2000 / 3000 字）→「开始扩写」。AI 只根据前文
（本章已写的内容、剧情记忆、前几章摘要与设定库）续写**当前这一章**，不会写到下一章。完成后自动打开结果：
- 「插入到章末」：续写接在本章最后（上一句写完了就另起一段）。插入前的内容存为历史版本「AI 扩写前」，插入后也可以在编辑器中按 Ctrl+Z（Mac 为 ⌘Z）撤销；同一次扩写不能重复插入。
- 扩写之后你又改了本章，插入时会提醒续写可能衔接不上，确认后才插入。
- 也可以「复制」后自己挑着用，或「重新扩写」再要一版。
- 篇幅越长需要的输出越多，所选模型的「最大输出」不够时会提示调大。

## 5. 剧情记忆

工作区左侧「剧情记忆」。剧情记忆是作品的「备忘录」：主线进展、主要人物的现状、尚未解决的冲突与伏笔、最近的情绪走势，
以及每次更新时新发生的关键事件。审稿、设定与角色一致性检查、灵感胶囊和智能扩写都会参考它，长篇写到中后期也能基于已有剧情判断，
而不是凭空推断。

- **自动更新**：每新写满约 3000 字自动更新一次（保存后几秒内开始，在后台进行，不影响写作）。只会把新写的内容发给模型，已经记录过的章节不会重复发送。
- **第一次给已有的长篇建立**：尚未记录的正文超过 3 万字时不会自动开始，打开「剧情记忆」点「立即更新」开始（会显示大致用量）。
- **检查较早的章节时**只参考那一章之前的剧情，不会把后面的发展当成前情。
- **改过已经记录的章节**：小的修改不影响；大段改写后剧情记忆可能过时，可以点「重建」从头建立（会重新消耗 token）。
- 需要一个模型：在「设置 → 模型 → 默认模型」中为「剧情记忆」选择模型；不单独设置时沿用「章节摘要」或「编辑审稿」的默认模型。更新失败（如断网）时，在「剧情记忆」中点「重试」。

---

## 6. 设定库

工作区左侧「设定库」。

- **AI 抽取设定**：从正文中抽取人物、地点、势力、物品、规则等。每条事实都附原文引文和来源章节；
  正文没改过的章节不会重复抽取。
- **待审核**：按条目分组、出现次数多的在前。可以「接受全部」「合并到已有条目」「编辑后接受」或「拒绝」；
  拒绝过的候选以后不会再出现。同名的一组候选可以一次接受，会合并成一个条目。
- **条目**：可以手动新建、修改名称与别名、增删事实。事实分「可变」（境界、位置、伤势、持有物、关系等会随剧情变化的）与「不变」；
  一致性检查时，可变事实只取「截至上一章」的最新值，所以合理的剧情变化不会被当成矛盾。
- 名称和别名在设定库中不能重复；重名时会提示合并到已有条目。
- 设定库中的名称也会作为错别字检查的专名白名单，减少把人名、地名误判为错字。

---

## 7. 技能

「设置」→「技能」：内置技能对应每类检查的规则，可以查看内容。

- **SkillHub**：搜索并安装社区技能（如特定平台的审稿标准），安装前可以查看安全报告。
- **本地导入**：导入 zip 或文件夹形式的技能（只保留 `.md` / `.txt` 文件）。
- 已安装的技能可以启用、停用、删除，并指定适用于哪些检查类型；在「AI 检查」中选择要用的技能。

## 8. 数据、备份与恢复

| 平台 | 数据目录 |
|---|---|
| Windows | `%APPDATA%\NovelEditor\`（资源管理器地址栏输入 `%APPDATA%\NovelEditor` 回车） |
| macOS | `~/Library/Application Support/NovelEditor/`（访达中按 ⇧⌘G 粘贴路径） |

「设置」→「关于」中也会显示当前的数据目录。目录内容：

```
NovelEditor/
├─ works/      每部作品一个 .novel 文件（SQLite 数据库，文件名是作品 id）
├─ backups/    每日自动备份：每部作品每天第一次打开时备份一份，保留最近 7 天
├─ trash/      删除的作品
├─ skills/     已安装的技能
├─ logs/       运行日志（保留 7 天，API Key 已脱敏）
├─ config.json 程序配置
└─ llm.json    模型配置（含 API Key，请勿发给他人）
```

- **手动备份 / 换电脑**：先退出程序，再复制整个数据目录；在新电脑上放到同样的位置后启动即可。
- **从每日备份恢复某部作品**：
  1. 退出程序。
  2. 在 `works/` 中找到该作品的文件——作品 id 就是打开这部作品时浏览器地址栏里 `/works/` 后面的那一段。
     先把 `xxx.novel` 改名留底（如 `xxx.novel.bak`）；同名的 `xxx.novel-wal`、`xxx.novel-shm` 如果存在也一并改名。
  3. 把 `backups/xxx/` 中想要的那一天的 `YYYYMMDD.novel` 复制到 `works/`，改名为 `xxx.novel`。
  4. 重新启动程序。
- **只想找回某一章的旧内容**：用「历史版本」恢复即可，不需要动文件。
- **指定其他数据目录**（高级）：启动时加参数 `--data-dir <目录>`，或设置环境变量 `NE_DATA_DIR`。

## 9. 常见问题

- **浏览器没有自动打开**：再双击一次程序；或者查看控制台窗口（Mac 为 `logs/launcher.log`）中打印的地址，手动复制到浏览器。
- **页面提示「会话已失效」**：从程序重新打开页面（再双击一次程序），不要直接收藏或刷新旧的登录地址。
- **页面右上角显示「本地服务未连接」**：程序可能已退出。重新启动后，未保存的内容会从浏览器草稿同步回来。
- **AI 检查失败**：任务列表中会显示原因（Key 错误、额度不足、模型名错误、网络问题等）。在「设置 → 模型」中修正后，回到任务点「重试」。
- **AI 检查一直停在某个进度**：多半是模型请求在等超时。任务下方会提示「模型连接异常」；「设置 → 模型」里会显示原因和处理建议。修正配置后，进行中的请求会按新配置自动重发。
- **端口被占用**：程序会自动换一个可用端口，并在下次启动时沿用。
- **排查问题**：日志在数据目录的 `logs/` 中，可以把当天的日志文件发给开发者（其中的 API Key 已脱敏）。
